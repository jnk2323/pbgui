# v2.10.5

## Fixes and improvements

- Restore saved Training/Holdout plans when opening, continuing or reusing PB8 optimizer results and Pareto configurations. Validate result-owned metadata against the native training suite and normalize midnight timestamps without changing dates. Invalid or unrelated metadata produces a visible error instead of silently dropping Holdouts. All tool-capable AI providers can retain a selected strategy and import the exact Suite from an explicitly identified original optimizer run, including base dates, exchanges and reducer. Individual validation backtests do not define the original training plan; stale generator drafts cannot replace imported windows.

- Start one prepared normal Vast optimizer directly from its Queue row or log details without an AI conversation. Review the frozen job, saved GPU/rental budget and duration, and convergence rule before authorizing one rental. Other jobs, shared queue pause state and Auto rent remain unchanged. Private bounded reviews bind the user, job, account and cost/control snapshot; retries recover the same rental identity. Recheck Stop/Cleanup and input ownership after account preflight, and prevent old unpaid reservations from reclaiming reassigned jobs.

- Add the same approval-gated normal Vast optimizer workflow to all tool-capable AI providers, without creating an AI Loop. Preserve native input preparation, automatic GPU sizing, per-job convergence and cleanup. Single-job approvals work while the shared queue is paused; a later Pause/End still cancels stale starts. Local optimizer tools explicitly require a local execution target. Failed prelaunch journals cease blocking API restart only when native evidence proves that no process or rental began.

- Support up to 20 million iterations in normal Vast optimizer validation and export. Accept the pinned worker's scalar scoring reducers without requiring an artificial scenario suite; conflicting named-scenario settings remain rejected before rental.

- Include selected PB7/PB8 Backtest Results in shared AI page context, including AI Loop comparison rows. Opaque result resources identify the exact selected configuration without exposing host paths. Tool-capable AI providers can propose independent PB8 backtests directly from a selected result with explicit dates and separate exchanges, preserving strategy, risk, coins and sparse overrides. Queueing still requires approval and uses the existing idempotent workflow.

- Fix Claude rejecting the complete PBGui tool catalogue once it exceeds 64 definitions. Catalogue capacity is separate from the unchanged 64-call execution budget. Invalid catalogues receive a distinct error; unexpected tools remain blocked.

## Validation

- 2,570 focused offline tests passed, including the installed Claude SDK against a local synthetic model server, isolated browser checks, approval/replay and queue controls, and Training/Holdout restoration. The mandatory test-selection gate requested focused validation for this patch release.
