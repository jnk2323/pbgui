# v2.10.4

## Fixes

- PBRun continues draining PB7 stderr and PB8 combined output when diagnostic logs cannot be opened or written, including on full disks. Logging retries after a bounded delay without pausing output consumption. Diagnostic lines consumed while logging is unavailable are discarded.

- AI Loops explicitly label training-window mean, minimum and maximum metrics for every provider. Native summaries and independent CPU observations consistently compare worst-window risk and mean return. Missing native extrema remain unavailable; older CPU evidence is labelled only from matching retained reports. Broad scoring exploration and CPU qualification remain unchanged.

- AI Loop broad-search evidence provides exact endpoint-change thresholds, and rejection feedback shows actual versus required changes. Exact 25% changes tolerate floating-point rounding; genuinely smaller changes remain rejected. Exploration, hard targets and fixed windows remain unchanged.

- AI Loop schemas and backend validation preserve approved worker settings for every provider, including the complete GPU block, CPU count, legacy population alias and Auto/null values. Continuations inherit source-run worker settings. Strategy, scoring and bounds experiments remain available.

- Loop detail reads and snapshot comparisons use bounded background processes to prevent CPU-heavy work from starving archive decoding. Overlapping detail requests for the same run share one report build; snapshot comparisons remain separate. Ownership and integrity checks remain enforced, and readers are joined at API shutdown without affecting native jobs. Automatic updates preserve valid reads, newer status and requested rounds, clear recovered errors, and show current status instead of historical pause reasons for active searches.
